Build Notes

Notes from the build.

Short, honest, and specific. Each note is tied to something that actually shipped.

369 skills, one library

We indexed 544 skills across the portfolio's repos and collapsed them into 369 canonical, deduplicated skills — every one with LLM-agnostic frontmatter, collision-resolved naming, and broken references logged for repair. The library now ships as one marketplace catalog (SkillCo), one Rostr project with 369 skills, and per-skill distribution zips. The lesson: treat skills like a product catalog, not a folder of markdown — naming, metadata, and dedupe are the product.

Rostr is infrastructure, not a demo

The Rostr runtime serves a live v1 API with agent definitions, skills, tool policies, and orchestration — the same runtime that powers client-facing work through Salesgency. Build the platform once; every product and engagement borrows it. The lesson: shared infrastructure only works when it has a versioned API and a real consumer on day one.

The $199 portal: productize the repeatable

Salesgency's most repeated engagement pattern — a GTM workflow build — became a self-serve paywalled wizard that outputs a personalized n8n workflow package. The lesson: watch what you build twice, then productize it before the third time.

Move to managed everything

When the Lola app's self-hosted database went unreachable, we moved to managed Postgres with connection pooling — and verified signup end-to-end the same day. The lesson: at portfolio scale, undifferentiated infrastructure is a liability. Buy the boring parts.

Kill the dashboard instinct

The corporate site carries no dashboards, checkout, or account creation. It earns trust and routes visitors — Salesgency and the product sites do the transacting. The lesson: every site gets one audience, one promise, one next step.
